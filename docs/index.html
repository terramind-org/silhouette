Silhouette

Skeleton loading states for SwiftUI, traced from the view you already have. Nothing to draw twice, and nothing on the page moves when the data lands.

Swift Package https://github.com/terramind-org/silhouette.git
Read the docs View on GitHub

The skeleton is your view.

Silhouette lays out your own view with sample data, out of sight, and shimmers in its exact outline until the real data arrives.

Traced, not hand-drawn

A bar for every line of text as it actually wraps, a block for each image, control and painted shape. Change the view and the skeleton follows.

No layout jump

The content has held its space the whole time, so it fades in where its skeleton was. New data of a different height eases into place.

One shimmer

Every skeleton keeps time by the same clock and its place on screen, so a card that appears late joins the band already in step.

Reveals that read well

Fast data never shows a skeleton. Slower data comes in row by row down the screen, each line wiping in where its bar was.

Remembers the shape

Each skeleton is drawn next time from what was really shown, even after a relaunch, keeping only the layout and never the data.

At home on Apple platforms

Dynamic Type, dark mode, VoiceOver, Reduce Motion and right-to-left layouts, on iOS, macOS, tvOS, watchOS and visionOS.

Wrap it once.

Pass the data, which is nil while it loads, and a sample of it. That is the whole integration.


import Silhouette

struct ProfileScreen: View {
    @State private var user: User?

    var body: some View {
        Skeleton(user, sample: .sample) { user in
            ProfileCard(user: user)
        }
        .task { user = try? await api.user() }
    }
}
  1. Your view is built from the samplelaid out where the real one will go, at full size but never seen.
  2. A copy is tracedeach line of text becomes a bar trimmed to the font, everything else keeps its shape.
  3. The real data landsand the content replaces its skeleton in the space it already held.
